# Penetration Test Report — Nineveh

![Difficulty](https://img.shields.io/badge/difficulty-Medium-orange) ![OS](https://img.shields.io/badge/OS-Linux-red) ![Focus](https://img.shields.io/badge/focus-LFI%20%2F%20port%20knocking%20%2F%20chkrootkit-lightgrey)

## Executive Summary

An authorized assessment of `target.htb` chained several weaknesses into full compromise: a brute-forced phpLiteAdmin v1.9 console allowed PHP code to be written to disk; a local file inclusion flaw in a separate web application executed that code; an image in an exposed directory contained SSH keys; and a `knockd` port-knocking sequence opened the SSH service. Privilege escalation abused a vulnerable `chkrootkit` cron job to obtain root.

## Findings Overview

| # | Finding | Severity |
|---|---|---|
| 1 | phpLiteAdmin v1.9 with weak credentials → authenticated RCE (EDB-24044) | High |
| 2 | Local File Inclusion in `/department` application | High |
| 3 | Private SSH key embedded in a publicly accessible image | Critical |
| 4 | Vulnerable chkrootkit executed as root (EDB-33899) | High |

## Technical Walkthrough

### 1. Enumeration

```bash
nmap -sC -sV target.htb
```

Only Apache on ports 80 and 443. Directory enumeration (DirBuster, lowercase medium list) found:

- `https://target.htb/db/` — **phpLiteAdmin v1.9** login
- `https://target.htb/secure_notes/` — a single image
- `http://target.htb/department/` — a login page

### 2. phpLiteAdmin — Brute Force + RCE

Hydra against the HTTPS login form with `rockyou.txt` succeeded:

```bash
hydra -l none -P rockyou.txt target.htb https-post-form \
  "/db/index.php:password=^PASS^&remember=yes&login=Log+In&proc_login=true:Incorrect password" -t 64 -V
```

phpLiteAdmin v1.9 allows creating a database whose file lives on disk with an attacker-chosen extension (EDB-24044). A database named `ninevehNotes.txt.writeup.php` was created; a table entry carried a PHP payload. The *Rename Database* page revealed the storage path: `/var/tmp/`.

### 3. LFI to Execute the Payload

The `/department` login revealed usernames via distinct error messages; `admin` was valid. Hydra recovered its password:

```bash
hydra -l admin -P rockyou.txt target.htb http-post-form \
  "/department/login.php:username=admin&password=^PASS^:Invalid Password" -t 64 -V
```

The *Notes* page was vulnerable to LFI but restricted to filenames containing `ninevehNotes.txt` — exactly why the database was named as it was:

```
/department/manage.php?notes=/var/tmp/ninevehNotes.txt.writeup.php
```

The PHP payload executed — code execution on the host.

### 4. SSH via Keys in an Image + Port Knocking

`strings` on the image in `secure_notes` exposed a public **and private** SSH key, but no SSH port was listening. Reading `/etc/knockd.conf` (via the web shell) revealed the knock sequence:

```bash
for x in 571 290 911; do
  nmap -Pn --host_timeout 201 --max-retries 0 -p $x target.htb
done
```

SSH opened; login as `amrois` with the recovered key; user flag at `/home/amrois/user.txt`.

### 5. Privilege Escalation — chkrootkit

LinEnum flagged `/usr/sbin/report-reset.sh` (cron) cleaning `/reports/` — reports generated by **chkrootkit**. chkrootkit versions vulnerable to EDB-33899 execute `/tmp/update` as root. A malicious script was planted:

```bash
printf '#!/bin/bash\ncp /root/root.txt /tmp/root.txt; chmod 444 /tmp/root.txt\n' > /tmp/update
chmod +x /tmp/update
```

On the next cron run, the root flag was readable.

## Remediation

- Replace/remove phpLiteAdmin; enforce strong passwords and MFA on admin panels.
- Fix LFI: never include files from user-controlled input.
- Never store private keys in web-accessible locations; audit content for embedded secrets.
- Update chkrootkit; ensure root-run scripts never execute world-writable paths.
- Port knocking is not a security boundary — treat SSH keys as the control and protect them.
